# Миграции базы данных (Alembic + PostGIS)

В проекте используется **Alembic** для контроля версий схемы базы данных. Все файлы миграций (папка `alembic/versions`) должны находиться в системе контроля версий.

## Первичная настройка базы (после клонирования)

Если вы запускаете проект впервые, после поднятия контейнеров необходимо применить существующие миграции, чтобы создать таблицы:

```bash
docker-compose exec backend alembic upgrade head
```

> **Важно:** Перед выполнением убедитесь, что в базе активировано расширение PostGIS (обычно делается автоматически при инициализации БД). Если нет, выполните в `psql`: `CREATE EXTENSION IF NOT EXISTS postgis;`

## Работа с изменениями моделей

Если вы изменили модели SQLAlchemy и хотите обновить схему БД:

1. **Создайте новую миграцию:**
   ```bash
   docker-compose exec backend alembic revision --autogenerate -m "Short description of changes"
   ```

2. **Проверьте созданный файл:**
   Откройте новый файл в `alembic/versions/`. Из-за использования **GeoAlchemy2** убедитесь в следующем:
   - В начале файла есть `import geoalchemy2`.
   - Если создается колонка типа `Geometry`, в `sa.Column` стоит параметр `spatial_index=False` (так как индекс обычно создается отдельной командой `op.create_index` ниже в том же файле).

3. **Примените изменения:**
   ```bash
   docker-compose exec backend alembic upgrade head
   ```

## Особенности конфигурации

Для стабильной работы с PostGIS в проекте настроено:

- **Фильтрация системных таблиц:** В `env.py` через `include_object` игнорируются схемы `tiger`, `topology` и системная таблица `spatial_ref_sys`. Это предотвращает "засорение" миграций системными объектами PostGIS.
- **Пути поиска (search_path):** Для корректной работы индексов `GiST` рекомендуется, чтобы пользователь БД имел настроенный путь поиска:
  ```sql
  ALTER USER losk SET search_path TO public, tiger, topology;
  ```

## Устранение неполадок

### Ошибка: `Target database is not up to date`
Это значит, что в базе отмечена одна версия, а в коде появились более новые файлы миграций. 
**Решение:** Выполните `alembic upgrade head`.

### Ошибка: `NameError: name 'geoalchemy2' is not defined`
Alembic иногда забывает добавить импорт гео-библиотеки в авто-сгенерированный файл.
**Решение:** Добавьте `import geoalchemy2` в начало проблемного файла миграции вручную.

### Ошибка при создании индекса GiST
Если индекс на поле `location` не создается, убедитесь, что:
1. Выполнен `SET search_path TO public, tiger;`.
2. У вас установлена и активирована библиотека PostGIS в текущей базе.
